# Recovery Intelligence Foundations (Milestone 8 Hardening)

## Executive Summary
The **Recovery Intelligence Foundation** (`RecoveryIntelligenceService`) provides the deterministic, data-driven optimization and analytics backbone for RecoverAI. It operates strictly on observed historical strategy outcomes, applying Wilson score lower-bound confidence intervals, Economic Strategy Value optimization (paise per attempt), sample-size tier gating, hierarchical 4D $\to$ 3D $\to$ Baseline fallback tracing, and transparent propensity scoring.

---

## 1. Probability Objective vs Economic Value Objective

RecoverAI separates **Statistical Confidence** from **Economic Value**:

### A. Statistical Confidence ($\text{Wilson LB}$)
Strategy ranking uses the Wilson score interval lower bound at $z = 1.96$ ($95\%$ confidence level) to calculate the conservative recovery probability:

$$\hat{p} = \frac{\text{successes}}{\text{attempts}}$$

$$\text{Wilson LB} = \frac{\hat{p} + \frac{z^2}{2n} - z \sqrt{\frac{\hat{p}(1-\hat{p})}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$

This protects against small-sample traps (e.g. $1/1 = 100\%$ naive rate has Wilson LB $\approx 0.025$).

### B. Economic Strategy Value ($\text{Paise Per Attempt}$)
Revenue recovery requires optimizing monetary recovery rather than conversion rate alone.

$$\text{Expected Recovered Paise Per Attempt} = \text{round}(\text{Wilson LB} \times \text{avg\_transaction\_amount\_paise})$$

$$\text{Economic Strategy Value Score} = \text{Expected Recovered Paise Per Attempt} \times \text{Burden Penalty Factor} \times \text{Tier Weight}$$

#### Burden Penalty Factors:
- `PAYMENT_LINK`: $1.00$ (Standard direct link)
- `DELAYED_RETRY`: $0.95$ (Low friction, minor gateway load)
- `METHOD_SWITCH`: $0.90$ (Moderate customer effort)
- `REMINDER`: $0.85$ (Customer contact friction, minor fatigue risk)
- `NO_ACTION`: $1.00$ (Zero contact burden)

#### Sample-Size Tier Weights:
- `HIGH` ($>100$ attempts): $1.00$
- `MEDIUM` ($31-100$ attempts): $0.95$
- `LOW` ($10-30$ attempts): $0.85$
- `INSUFFICIENT` ($<10$ attempts): $0.50$ (Heavy evidence uncertainty penalty)

#### Trade-Off Example:
- **Strategy A**: $40\%$ rate on ₹100 transactions $\implies$ Expected recovery = ₹40 / attempt.
- **Strategy B**: $30\%$ rate on ₹5,000 transactions $\implies$ Expected recovery = ₹1,500 / attempt.
- **Result**: `StrategyRanker` identifies that Strategy B produces $37.5\times$ greater monetary recovery value per attempt and ranks Strategy B higher when policy permits.

## 2. Evidence Source & Provenance Model

To prevent synthetic data from being mistaken for real merchant history, evidence is tracked using two distinct fields:

### A. Evidence Category (`evidence_category`)
- `OBSERVED`: Unverified historical outcomes recorded in merchant environment datasets.
- `VERIFIED`: Authoritative Razorpay API / Webhook confirmed outcomes.
- `SIMULATED`: Local simulation engine experiment results.
- `PROJECTED`: Statistical / model-based estimates.

### B. Evidence Provenance (`evidence_provenance`)
- `SYNTHETIC`: Local synthetic evaluation dataset (`v1.0`).
- `RAZORPAY_TEST_MODE`: Confirmed in Razorpay Test Mode via API/Webhook.
- `RAZORPAY_LIVE_MODE`: Confirmed in Razorpay Production Mode.
- `SIMULATION_ENGINE`: Generated by local local strategy simulator.
- `PROJECTED_MODEL`: Derived from propensity scoring models.

#### Provenance Invariants:
- `OBSERVED + SYNTHETIC` $\neq$ `VERIFIED + RAZORPAY_TEST_MODE`.
- `SIMULATED` never silently becomes `VERIFIED`.
- `PROJECTED` never silently becomes `OBSERVED`.
- `SIMULATION_GROUND_TRUTH` is completely isolated in `data/simulation_truth/` and inaccessible to the optimizer.

## 3. Cold-Start Baseline Semantics

When canonical 4D, 3D, and Category Baseline segment evidence is `INSUFFICIENT` ($<10$ attempts across all levels):
- The recommendation is labeled: **`BASELINE_RECOMMENDATION`** (not "best strategy").
- Output fields:
  ```json
  {
    "recommendation_type": "BASELINE_RECOMMENDATION",
    "evidence_status": "INSUFFICIENT_EVIDENCE",
    "strategy_source": "DETERMINISTIC_BASELINE",
    "recommendation_rationale": "Selected default strategy PAYMENT_LINK because historical segment evidence is INSUFFICIENT (<10 attempts)."
  }
  ```
- Deterministic baseline recommendations remain **100% subject** to the Policy Engine, Trust Gate, Action Authorization Guard, and human review.

## 4. API Endpoints (`backend/api/routes/intelligence.py`)

- `GET /api/intelligence/portfolio`: Returns total revenue at risk, eligible revenue, projected recoverable revenue, and sample size tier counts.
- `GET /api/intelligence/segments`: Returns canonical 4D segment profiles and sample size tier distribution.
- `GET /api/intelligence/strategies/compare`: Returns deterministic Wilson strategy rankings, Economic Value Scores (paise), evidence categories, provenances, and rationale.
- `POST /api/intelligence/recoverability`: Computes transparent recoverability score and factor breakdown.
- `GET /api/intelligence/evidence-trace`: Returns step-by-step fallback trace for decision auditing.
